# Figma Make / Figma AI Prompt — TutorPair MVP V7

Design a polished, interactive, desktop-first responsive website prototype for **TutorPair**, a Thailand-based online tutoring platform for secondary-school students (M.1–M.6), tutors and parents. Continue an existing SaaS brand style: soft lavender/purple, white cards, pale gray backgrounds, warm friendly but credible typography, clear rounded inputs/buttons, readable spacing and English UI copy. Do **not** design it as a brand-new disconnected product. Build reusable components and variants with auto layout, mobile-friendly responsive behavior and consistent Student/Tutor/Parent sidebar navigation.

**Core rule:** BYOS (Bring Your Own Students) is an **enrollment source**, not a separate student/tutor account type. Students use **one Student account** for invited classes and TutorPair Matching. Tutors use one dashboard for all learners.

Create connected high-fidelity frames/screens for:

1. **Tutor Onboarding — About You:** name, university, faculty (optional), GPA/honors (optional, self-reported), "How do you teach?" textarea and experience. Never make a claim of verified GPA without an approved evidence check.
2. **Tutor Onboarding — Subject & Availability:** approved subject/grade scope, a 7-day recurring time-window selector (Mon–Sun, checkbox per day + start/end dropdown), hourly rate. Inline error below price input when below ฿100: **"Please enter at least 100 THB/hr."** Keep other fields intact.
3. **Tutor Verification:** two clearly labeled cards. Box 1: **Subject Knowledge Evidence** — PDF/JPG/PNG picker for transcript, student card or exam certificates. Box 2: **Teaching Ability Check (Required)** — Option A select MP4/MOV/WebM video (~3 min), **OR** Option B paste HTTPS video link. Include selected filename, local video preview, inline validation state, submission pending status and privacy note. In the prototype do not imply real file upload or secure identity verification.
4. **Student Learning Request:** 3-step form (academic goal/grade/subject; three optional preference dropdowns; four-session plan, weekly availability and budget). Package cards: Regular Pace (4 weeks ×1), Exam Rescue Sprint (2 weeks ×2), Emergency Cram (1 week ×4). Session duration 60/90/120 min. Inline cost preview: maximum budget per hour × four sessions × session duration. School worksheet is optional; no required specific-topics selection.
5. **Top 3 Tutor Match Cards:** polished cards with portrait placeholder, university and faculty, **illustrative** GPA/honors, rating + review count, platform completed lesson hours, sample renewal %, intro, and 4-session total price using tutor's hourly rate (platform fee excluded unless defined). Personalized **WHY MATCHED** must be a natural sentence, e.g. "P’Mew may be a good fit because this tutor teaches at a steady pace, uses practice drills, and lets you try first." Add preference tags, a collapsible **"Click here to see 3 mins Demo"** video player state (clearly marked illustrative sample), and identical baseline 4-lesson plan accordion across tutors. Distinguish real verified information from samples.
6. **Tutor Requests Inbox:** after a Student requests a tutor, show Pending response target 24 hours (proposed), Student note, worksheet filename, 4-lesson draft plan, Accept and Reject actions. After Accept, tutor can edit **all four topics plus a separate pacing control** (Guided / Balanced / Intensive) and click **"Send Plan to Student"**. Include a sent state.
7. **Student Booking Approval:** pending tutor → tutor accepted → plan sent → student/authorized parent review and approval → mock PromptPay checkout → enrolled. Display tutor-adjusted topics and pacing. All payments simulated, not escrow integration.
8. **Student Progress:** 4-lesson stepper (Done / This week / Upcoming), a 4-session punch card, Revision Vault with GoodNotes PDF metadata placeholders, after-class student feedback (clarity as three emoji faces + pace), session reschedule/cancel request and the updated status shown after tutor decision.
9. **Tutor Reschedule/Cancel Inbox:** direct actionable cards on the tutor dashboard/inbox for incoming session changes with the requested lesson, reason and **Accept / Reject** buttons, plus proposed 24-hour advance-notice disclaimer.
10. **Tutor After-Session Report:** student selector, engagement 1–3, previous homework checked toggle, a one-sentence session note, strengths, improvement, next task, optional GoodNotes PDF picker, and Parent/Student report preview. Explain that LINE notification is a future API integration, not sent by this prototype.
11. **Two-Sided Review:** after lesson 4, Student → Tutor and Tutor → Student each submit 1–5 stars and short text privately; show "Waiting for other review" and a separate "Revealed" preview when both submit or after 14 days. Treat these as proposed policy/demo states, not automatically public production reviews.
12. **Unified BYOS Journey:** Tutor creates a small group with capacity → generates an invite link → Student logs in or registers → accepts invitation → Mathematics BYOS class appears in their Student Dashboard → Student clicks **Find Another Tutor** → chooses Physics via Matching → both Mathematics (BYOS) and Physics (TutorPair) appear under **My Classes**. Same Student account, no second registration.
13. **Parent Dashboard & LINE Preview:** linked child, aggregated multi-subject progress, latest tutor note, monthly rating 1–5 and renewal intent, LINE Flex message preview with a secure "View Full Report" placeholder.
14. **Demo Mode testing bar:** top navigation mode switch between New Student, Active Student (3 sample classes), New Tutor, Active Tutor (3 sample ongoing classes), and Parent demo; clearly label sample data.

**Required interaction:** Provide clickable form states, validation messages, dropdowns, tabs, modals, expanded video preview, matching result selection, Tutor Accept/Reject, plan editing and approval, session status update and BYOS join sequence. Link all frames into 2 useful prototype paths: (A) Student request → Tutor request inbox → Student plan approval → progress; (B) Tutor BYOS invitation → Student joins → Find Another Tutor → two active classes.

**Visual quality:** airy modern education SaaS, purple primary (#6D63D9 or matching existing palette), warm white cards, neutral status colors, consistent input border radii and iconography; avoid excessive gradients or crowded slides. Support 1440px desktop and 390px mobile layouts; consider accessible contrast, keyboard focus, field errors and loading/empty states. Keep labels in English and actions concise. Use only fictional demo names, data and university affiliations; mark any fabricated ratings, verified hours and renewal data as SAMPLE.

**Important implementation truthfulness:** This is an interactive visual prototype. Do not claim real API, AI worksheet reading, payment escrow, LINE messages, cross-device BYOS invites or identity verification. Expose UI-ready integration points and clearly marked demo-only interactions.
